# CODoH Leakage Simulator — Specification

This is the implementation spec for the protocol-logic simulator and post-hoc
attacker that produce the leakage analysis committed in
`revision-commitment.txt` priority item 1. It is anchored to the experiment
plan in `experiment-plan.md` and the threat model in `rebuttal-experiments.md`.

The simulator lives at `codoh-evals/sim/` (flat module). Data collection is a
separate task. Until real per-entry traces land, simulator development uses a
synthetic trace generator that emits the same schema.

---

## 1. Goal

Quantify residual leakage in CODoH under realistic client behavior and produce
a recommended `(B_min, T_max)` operating region. One simulator + one attacker
log feeds three analysis lenses:

- **(a)** Popularity-conditioned identification (Zipf-rank buckets).
- **(b)** Page-load sequential-query attack (cross-batch union).
- **(c)** Long-term intersection attack (multi-day persistent adversary).

---

## 2. Threat model

The adversary observes `S'`, the set difference between cache states across a
batch commit. From `S'`, it tries to (i) identify the victim's page or (ii)
narrow the candidate-page set.

- **Weak attacker:** observes only `S'`. Reported as a secondary baseline.
- **Strong attacker (primary):** also knows the non-victim *real* queries
  injected in the same batch. Subtracts them from `S` to get
  `S' = victim_real ∪ all_covers` (covers from victim AND non-victim queries
  remain in `S'`, since covers are sealed inside the target→enclave bundle and
  the attacker cannot read them).
- **Out of scope:** target collusion (revealing cover sampling), SGX
  microarchitectural side channels.

Lens (c) assumes **perfect linkage** across days (proxy can link the same
client by IP/connection — standard worst case).

## 3. Inputs (data contract)

### 3.1 Per-entry trace CSV (consumed by simulator)

Schema produced by `benchmark-har.py` (file: `entries_har_<strategy>.csv`,
written alongside the existing aggregated `results_har_<strategy>.csv`).
Trace collection uses the `vanilla` strategy: `Q_w` and per-entry timings are
properties of the page, not the resolver, so the cheaper non-DoH path
suffices. (Aside: vanilla yields tighter inter-arrivals than DoH would, so
lens-(b) batch-spanning is a lower bound — conservative for the attacker.)

**Sentinel `dns_ms = 0`**: rows with `dns_ms == 0` represent DNS queries the
browser emitted that **never resolved** (NXDOMAIN / SERVFAIL / timeout). The
HAR pipeline cannot recover their resolution latency, but the query still
reaches the resolver in production, so the simulator must include them in
`Q_w` and slot them into batches at `started_offset_ms`. Treat `dns_ms == 0`
as "instant" for batch-arrival purposes (the query enters the pending buffer
at `started_offset_ms`; it never gets a response, so timing of any downstream
phase is undefined).

```
rank, site, run, day, hostname, started_offset_ms, dns_ms
```

One row per resolved DNS entry, ordered by emission. `started_offset_ms` is
relative to the page-load start.

**Single-day collection only.** The `day` column exists for forward
compatibility but is expected to hold one value (or be absent) for the
revision. Multi-day analysis (lens c) is generated by replaying this
single-day trace as multiple synthetic days inside the simulator (see §8.3).

The simulator builds an in-memory index:

```python
trace[(site, run, day)] = [
    (hostname_1, offset_ms_1),
    (hostname_2, offset_ms_2),
    ...
]
Q_w[site] = sorted unique set of hostnames across all (run, day) for that site
```

### 3.2 Reference set

CrUX top-10k origins (Chrome User Experience Report, magnitude bands 1k +
5k + 10k), filtered to those that resolve via DNS — 9,869 origins
(`data/crux-top10k-resolvable.csv`). Each origin is a full host (`scheme +
hostname`); subdomains are first-class entries (e.g., `www.facebook.com`,
`m.facebook.com`, `business.facebook.com` are three distinct pages),
matching what real users actually navigate to.

`Q_w` is collected for the full set. Pages with `|Q_w| < 3` are kept as-is
in the reference set; they may inflate candidate-set sizes for trivial-match
S' — this is reported, not filtered.

**All-3-runs-intact filter (added 2026-05-05).** Trace validation showed
8.71% of `(site × run)` pairs are missing in `runs/crux-combined-r1-r3/`,
unevenly distributed across sites. `trace_loader.py` filters the lens-(a)
victim pool to sites with all 3 runs present *before* magnitude-band
sampling, so the per-bucket `n` advertised in §8.1 is the actual `n`. The
post-filter bucket counts are reported alongside the bucket figures.

CrUX exposes ranks at log-magnitude resolution only (top-1k / top-5k /
top-10k), not exact positions. The simulator's stratification is therefore
on magnitude bands rather than fine Zipf rank (see §8.1).

**Why CrUX over Umbrella.** Umbrella ranks by DNS query volume, which
favors infrastructure hostnames (e.g., `1e100.net`, `3gppnetwork.org`,
ad-serving CDNs) that are not browsable webpages. Of Umbrella's top-100,
~42% failed headless-browser load in our pilot crawl. CrUX ranks by real
Chrome page navigations, so its top-10k is dominated by browsable pages
that match the simulator's threat model (a user navigates to a page, the
client emits the page's DNS query set). Umbrella ∩ CrUX top-10k overlap is
only 287/10,000 — the two sources answer fundamentally different questions.

### 3.3 Synthetic trace generator (development bridge)

Until real CSVs land, a generator produces synthetic per-entry rows with the
same schema. Per page, draw `m ~ NegBinomial(mean=8, dispersion=4)` distinct
domains; emit them with offsets drawn from a heavy-tailed inter-arrival
distribution (lognormal, μ=200ms, σ=1.0). Used only for plumbing and unit
tests; replaced with real data before any reported result.

## 4. Background traffic model

Background = N concurrent users, where N ∈ {10, 100, 1000} (this is the
`λ_bg` axis).

Each background user emits, **independently**:

- **Bursts:** every ~30s (Poisson-jittered), pick a random page from the
  top-10k crawl and emit its `Q_w` queries with realistic inter-arrivals
  (replayed from the page's trace if available, otherwise lognormal).
- **Idle Poisson heartbeat:** 0.01 qps (1 query per 100s on average) of
  random domains drawn from the cover universe (CrUX top-1M, §6.2).

Both streams flow into the same enclave batch buffer as the victim's queries.

**Why both:** bursts produce realistic co-tenant correlation in batches (good
for lens b); idle Poisson keeps `B_eff` from underflowing in low-N regimes.

**Aggregate qps under default:** 100 users × (8 queries / 30s + 0.01 qps) ≈
27 qps + 1 qps = ~28 qps.

---

## 5. Cache model

### 5.1 Capacity

`N` is a swept axis: `N ∈ {256, 1024, 4096}`. Default for headline = 1024
(matches Config 5 in `evaluation.tex`). Eviction = LRU.

### 5.2 Pre-cached entries

If a domain is already in the cache when its commit fires, it is **suppressed
from `S'`** (no-op insertion; matches `experiment-plan.md §4.3`).

### 5.3 Initialization

Two modes, both reported:

- **Cold (headline):** empty cache. Maximally pessimistic for privacy.
- **Warm (ablation):** per-cell, run a burn-in until the cache reaches `N`
  unique entries via background traffic only (no victim). Snapshot and reuse
  across all trials in that cell.

---

## 6. Batch commit logic

The enclave commits a batch when:

- **Size trigger:** `|unique queries in pending| ≥ B`.
- **Time trigger:** `Δt since first pending query ≥ T_max`.

Trigger choice is configurable. **Default = deterministic at B.**
Probabilistic-around-B (`p=0.1` per query once `|q| ≥ B`) available as a
sensitivity ablation.

### 6.1 Underflow (T_max with `B_eff < B_min`)

When `T_max` fires with fewer than `B_min` unique queries pending:

- The enclave **disables cache hits and reverts to baseline ODoH**.
- Pending insertions are **discarded** (no commit, no `S'` contribution).
- The `B_eff = 0` event is logged for the cell-level "underflow rate" metric.

### 6.2 Cover sampling per batch

For each real query in the batch, the target draws `k` covers **i.i.d. from
`D` with replacement**. Total covers per commit = `B_eff × k` (collisions
permitted; reduce `|S'|`).

`D` is configurable; universe = **CrUX top-1M** (`data/crux-202603.csv`,
schema `origin,rank` with magnitude-band ranks {1k, 5k, 10k, 50k, 100k,
500k, 1M}). Per-origin Zipf weight is the average mass of a 1/r Zipf
integrated across each band (decision #47):

- `matched` (headline): empirical Zipf over CrUX top-1M.
- `uniform`: uniform over CrUX top-1M.
- `stale`: uniform over a random 50% subset of CrUX top-1M (frozen).

CrUX (origin-ranked by real Chrome navigations) is used for both the
reference set (§3.2, top-10k) and the cover universe (top-1M); the two
roles use different files but the same source — so cover draws can land
inside the candidate set, which is exactly the regime that makes covers
hard to distinguish from real queries.

## 7. Attacker model

### 7.1 S' construction

For each commit, compute the inserted multiset `S` (post-suppression of
pre-cached entries). Strong attacker subtracts the multiset of background
*real* queries it knows about, leaving:

```
S' = victim_real ∪ all_covers
```
Both victim's k covers AND all non-victim queries' B_eff×k covers remain.

### 7.2 Candidate set (primary metric)

For each candidate page `w` in the reference set (top-10k):

```
score(w, S') = |Q_w ∩ S'| / |Q_w|
```

`w` is in the candidate set if `score(w, S') ≥ α`. Default `α = 0.5`;
sensitivity `α ∈ {0.3, 0.5, 0.7}`.

Matching is on **full FQDN** (no eTLD+1 collapse).

Reported per-cell:

- median candidate-set size
- p10 / p90
- fraction of trials with size = 1, ≤ 5, ≤ 10

### 7.3 Ranking (secondary metric)

Rank candidate pages by descending `score(w, S')`. Reported:

- top-1 accuracy: highest-scoring page is the true victim
- top-5 accuracy
- mean reciprocal rank (MRR) — supplementary

### 7.4 Closed-form sanity check

Implemented for two cases, both gated as unit tests:

1. **Single-batch independent uniform-D:** posterior of victim identity
   converges to `1 / (1 + B_eff·k)`. MC over 10⁵ trials must match within 2σ.
2. **Per-batch lens (a) under D = Q:** identification accuracy as a function
   of victim Zipf rank — analytic for the head bucket. MC against the closed
   form; assert convergence.

## 8. Three analysis lenses

All three consume the same per-trial JSONL log produced by the simulator.

### 8.1 Lens (a) — Popularity-conditioned identification

Stratify victims by CrUX magnitude band (capped at top-10k). CrUX ranks
are bucketed at log magnitudes — finer Zipf positions are not available —
so the head bucket is "top-1k" rather than "top-100":

- **top-1k** (`rank ≤ 1000`, 994 origins after resolvability filter — use all)
- **1k–5k** (`1000 < rank ≤ 5000`, sample 200 pages per cell from 3,956 origins)
- **5k–10k** (`5000 < rank ≤ 10000`, sample 200 pages per cell from 4,919 origins)

Per victim page, **30 trials** with different background-user seeds and cover
samples (single global RNG seed; trial seed = global + cell_id + victim_id +
trial_idx).

Per bucket × cell, report candidate-set size and top-1 accuracy.

### 8.2 Lens (b) — Page-load sequential-query attack

**Headline lens (amended 2026-05-05).** Trace validation: per-page query
count median = 8 but **p99 = 142** and **max = 540**. At every `B` in the
default grid, a heavy fraction of CrUX pages spans multiple commit windows,
so cross-batch union is the *modal* attacker behavior, not an edge case.
The master `(B, T_max)` heatmap (sim-spec §10.4) is therefore derived from
**lens (b) top-5 page-ID accuracy**; lens (a) per-bucket numbers explain
the heatmap's shape across popularity strata.

Victim emits the page's full `Q_v` over the page-load span (per-entry
timestamps, driven by `started_offset_ms` — which is verified monotonic).
Failed-DNS rows (`dns_ms=0`, 19.17% of trace) are first-class observables
to the proxy/adversary and feed the batcher exactly like resolved rows.
Some queries land in batch `i`, others in batch `i+1`, possibly `i+2`+ if
span exceeds T_max.

**Attacker observation:** union over all batches whose commit window contains
at least one of the victim's queries:

```
S'_total = ⋃_{i ∈ batches_touched_by_victim} S'_i
```

Score and rank candidate pages against `S'_total`.

Per trial, log:

- `|S'_total|`
- per-batch `|S'_i|` distribution
- number of batches the victim's queries spanned
- top-1 / top-5 page-id accuracy

### 8.3 Lens (c) — Long-term intersection attack

**Multi-day data is fully synthetic.** We do not crawl across multiple real
days. Instead, the simulator replays the same single-day trace as `D`
synthetic "days," with each day getting:

- a fresh background-traffic sample (new `BackgroundUserPool` seed),
- per-day jittered victim timing (intra-day query offsets perturbed by
  ±10% lognormal jitter; pages visited in a freshly randomized order),
- a fresh cover-sampling RNG stream (new commits → new covers, even though
  `Q_v` is identical across days).

This matches `revision-tasks.md §1.0.6` — bootstrap-resampled multi-day from
one day's trace.

Synthetic user with **fixed repertoire** of 10 popular pages (drawn from
the CrUX top-1k bucket; same 10 every day). Each synthetic day:

- 8h active window with realistic ~30-min gaps; all 10 pages visited in
  randomized order (re-shuffled per day).
- 16h idle (no victim activity; background continues).

Over `D ∈ {1, 3, 7}` synthetic days (extend to 14 if compute permits, not
committed):

Per day `d`, compute the per-page candidate set:

```
C_d = {w ∈ reference_set : score(w, ⋃ S'_d) ≥ α}
```

(using the union of *all* batches the user's queries touched that day).

**Days-to-fingerprint** = smallest `D` such that:

```
|⋂_{d=1..D} C_d| ≤ |R| = 10
```

**Reporting axes (per commitment):** days-to-fingerprint is reported against
all four axes the commitment names: `(B, T_max, k, λ_bg)`.

- **Headline:** heatmap over `(B, T_max)` at default `(k=3, λ_bg=100u,
  N=1024, α=0.5, D=matched, cold)`.
- **Supplements:**
  - line plot of days-to-fingerprint vs. `k` (at default B, T_max, λ_bg)
  - line plot of days-to-fingerprint vs. `λ_bg` (at default B, T_max, k)

Bayesian posterior ≥ 0.9 reported as a robustness check.

## 9. Parameter sweep

| Axis      | Values                                 | Notes                              |
|-----------|----------------------------------------|------------------------------------|
| `B`       | {5, 10, 20, 50, 100, 256, 512}         | privacy axis (extended 2026-05-05) |
| `T_max`   | {30, 60, 300, 600, 1800} s             | PC mandate                         |
| `k`       | {1, 3, 5, 10}                          | cover-noise axis                   |
| `λ_bg`    | {10, 100, 1000} concurrent users       | traffic-rate axis                  |
| `N`       | {256, 1024, 4096}                      | cache-size axis                    |
| `α`       | {0.3, 0.5, 0.7}                        | metric sensitivity                 |
| `D`       | {matched, uniform, stale}              | cover-distribution sensitivity     |
| init      | {cold, warm}                           | cache-init sensitivity             |

**`B` upper end extended to 512 (2026-05-05).** Trace validation showed
per-page max = 540 queries; without `B ≥ 256`, every cell stays in the
"victim page spans many batches" regime and the single-batch leakage
behavior at large `B` is never observed.

Full grid: 7×5×4×3×3×3×3×2 = **22,680 cells** × 200 victim pages × 30 trials
≈ 136M trial-batches. The adaptive scale-up below keeps the actual run
bounded.

### 9.1 Adaptive scale-up

Run in three stages:

1. **Smoke (3×3 corners):** `B ∈ {5, 20, 100}`, `T_max ∈ {30, 300, 1800}` at
   default `(k=3, λ_bg=100u, N=1024, α=0.5, D=matched, cold)`. ~9 cells ×
   200 × 30 ≈ 54k trials. Should run in <10 min. Validates plumbing and
   metric implementations.

2. **Default-axis sweep:** Full 5×5 `(B, T_max)` grid at default other-axes,
   cold and warm. ~50 cells × 200 × 30 ≈ 300k trials. Produces preliminary
   master heatmap.

3. **Full grid:** Expand only if pilot results show variation along an axis.
   Worst case, all 16,200 cells.

### 9.2 Heatmap defaults (when fixing other axes)

`k=3, λ_bg=100 users, N=1024, α=0.5, D=matched, cache=cold`.

Master heatmap: two panels (cold + warm) on the same `(B, T_max)` grid.

## 10. Output schema

### 10.1 Raw per-trial JSONL log

One line per trial. Path: `out/raw/cell_<cell_hash>/trials_<chunk_id:04d>.jsonl.gz`
(chunked across victim shards — see decision #49). Implemented schema (per
decision #48 — scored `AttackResult` dicts in place of raw `batches[].S_prime`):

```json
{
  "cell_hash": "0874200bf679",
  "victim_site": "example.com",
  "victim_rank": 437,
  "bucket": "1k-5k",
  "trial_idx": 17,
  "n_commits": 707,
  "n_victim_batches": 1,
  "underflow_count": 1,
  "S_prime_total_size": 64,
  "Q_v_size": 4,
  "lens_a": [
    {"cand_size": 15, "top1": false, "top5": false, "rr": 0.34,
     "victim_score": 1.0, "g": 0, "t": 8}
  ],
  "lens_b": {"cand_size": 15, "top1": false, "top5": false, "rr": 0.34,
             "victim_score": 1.0, "g": 0, "t": 8}

```

Cell parameters live in `out/raw/manifest.json` (one entry per cell) — not
duplicated per-trial. To recover trial-level params, join on `cell_hash`.

Trade-off vs. the original schema: per-batch `S'` sets are not stored, so
re-scoring under a different α or reference set requires re-simulating. A
future `--store-batches` flag would emit raw S' alongside (per decision #48).

- `lens_b.csv` — one row per cell. Cross-batch-union page-ID headline.

cell_hash, B, T_max_s, k, lambda_bg, N, alpha, D, init,

`frac_cand_le_k` is keyed off the cell's own `k` (operator-tuned threshold);

### 10.4 (B_min, T_max) recommendation derivation

**Master heatmap is lens-(b) top-5 page-ID accuracy (amended 2026-05-05),**
shaded with the three nested operator-tier regions below. Lens (a) per-band
numbers and lens (c) days-to-fingerprint appear as separate panels /
companion tables.

The commitment requires recommendations "as a function of operator-chosen
privacy–performance targets, rather than fixing a single threshold." The
output is therefore **not** a single safe pair; it is a region (or Pareto
frontier) parameterized by operator targets.

**Operator targets (three tiers reported):**

| Tier | `tail_acc` | `page_id_acc@5` | `days_to_fingerprint` |
|---|---|---|---|
| Strict     | < 0.05 | < 0.10 | > 30 |
| Moderate   | < 0.10 | < 0.20 | > 14 |
| Permissive | < 0.20 | < 0.40 | >  7 |

Where:

- `tail_acc` = strong-attacker top-1 accuracy on the 5k–10k bucket (lens a).
- `page_id_acc@5` = top-5 page-identification accuracy on lens (b).
- `days_to_fingerprint` = lens (c) headline metric, intersection ≤ \|R\|.

**Master figure:** the `(B, T_max)` heatmap is shaded with three nested green
regions (Strict ⊂ Moderate ⊂ Permissive). Each cell takes the *worst* of the
three metrics. Operators pick a tier and read off the smallest `(B, T_max)`
that meets it.

**Companion table:** for each tier, list the minimum `(B_min, T_max)` that
qualifies, plus the achieved hit-rate / latency from the existing evaluation
in `evaluation.tex`. This ties privacy targets to performance cost.

The thresholds above are reported as the spec's defaults; reviewers can
re-shade with their own thresholds from the published per-cell metrics in
`out/agg/`.

## 11. Pseudocode

### 11.1 Per-trial loop

```python
def run_trial(params, victim_page, trial_seed):
    rng = np.random.default_rng(trial_seed)
    cache = init_cache(params.init, params.N, params.lambda_bg, rng)
    enclave = BatchBuffer(B=params.B, T_max=params.T_max,
                          B_min=params.B_min, k=params.k, D=params.D)
    bg = BackgroundUserPool(n_users=params.lambda_bg, rng=rng)

    victim_queries = trace[victim_page].query_stream()  # (hostname, t)
    end_t = victim_queries.last_t + params.T_max + 1

    log = TrialLog(victim_page, params)
    t = 0
    while t < end_t:
        # advance background
        for q, t_q in bg.next_until(t + dt):
            commits = enclave.submit(q, t_q, owner="bg")
            for c in commits: log.record(c, cache=cache)
        # advance victim
        for q, t_q in victim_queries.until(t + dt):
            commits = enclave.submit(q, t_q, owner="victim")
            for c in commits: log.record(c, cache=cache)
        # time-trigger check
        commits = enclave.tick(t + dt)
        for c in commits: log.record(c, cache=cache)
        t += dt

    return log
```

### 11.2 Commit / S' construction

```python
def commit(buffer, cache, k, D, rng):
    if buffer.unique_count < B_min:
        # underflow path
        buffer.clear()
        return Commit(B_eff=0, S_prime=[], underflow=True)
    real = buffer.real_queries
    covers = sample_covers(D, k * len(real), rng)  # i.i.d. with replacement
    inserts = real + covers
    # Pre-cache suppression (§5.2): the attacker only observes the cache-state
    # delta, which excludes pre-cached entries. `S` is therefore the
    # post-suppression insertions, NOT the raw `inserts` multiset (drift fix
    # 2026-05-05; aligns this listing with §7.1 prose).
    new_entries = [d for d in inserts if d not in cache]
    cache.add_all(new_entries)  # LRU eviction here
    S = new_entries
    # S' = S minus background-real-known (covers stay sealed; decision #10)
    S_prime = multiset_diff(S, buffer.bg_real_queries)
    return Commit(B_eff=len(real), S_prime=S_prime, underflow=False,
                  victim_in=buffer.victim_real,
                  victim_covers=[c for c in covers if c.from_victim])
```

### 11.3 Attacker scoring

```python
def candidate_set(S_prime, reference_set, alpha):
    S_set = set(S_prime)
    candidates = []
    for w, Q_w in reference_set.items():
        if len(Q_w & S_set) / len(Q_w) >= alpha:
            candidates.append(w)
    return candidates

def rank(S_prime, reference_set):
    S_set = set(S_prime)
    return sorted(reference_set.items(),
                  key=lambda kv: len(kv[1] & S_set) / len(kv[1]),
                  reverse=True)
```

## 12. Acceptance criteria

The simulator phase is complete when **all** of the following hold:

1. Closed-form sanity tests pass (uniform-D single-batch, lens-a head bucket).
2. Hand-checked trace unit test passes (a 5-page, 3-trial fixture with
   manually-computed expected `S'` and candidate sets). Fixture **must
   include** at least one `dns_ms=0` row inside a victim page; expected
   `S'` shows the failed-DNS hostname is observable in its batch (sim-spec
   §3.1, §8.2).
2b. Real-data regression test: `trace_loader.load(runs/crux-combined-r1-r3/)`
   reproduces the 27,025-page total and the empirical `|Q_w|` distribution
   from the validation run (median 8, p99 142, max 540), within bit-exact
   tolerance.
3. Pilot smoke run produces non-trivial gradient on `(B, T_max)` (top-1
   accuracy varies > 0.1 across the 3×3 corners).
4. **Headline figures generated:**
   - master `(B, T_max)` heatmap (cold + warm panels)
   - lens (a) bucket plot
   - lens (b) page-id accuracy + |S'_total| CDF
   - lens (c) days-to-fingerprint heatmap
5. **Sensitivity supplement generated:**
   - α ∈ {0.3, 0.5, 0.7} comparison
   - D drift (matched / uniform / stale)
   - cold vs. warm initialization
   - probabilistic vs. deterministic commit (one cell)
6. Per-cell underflow rate logged and reported (validates `B_min` reachability).

## 13. Code organization

Flat module under `codoh-evals/sim/`:

```
sim/
  trace_loader.py       # real CSV + synthetic generator (same schema)
  cache.py              # LRU cache, suppression of pre-cached on insert
  enclave.py            # BatchBuffer, commit logic, S' construction
  cover.py              # cover-distribution sampling (matched/uniform/stale)
  background.py         # BackgroundUserPool (bursts + idle Poisson)
  attacker.py           # candidate set, ranking, closed-form sanity
  trial.py              # run_trial, TrialLog, JSONL writer
  cells.py              # parameter cell expansion, sweep driver
  analyze_a.py          # lens (a) bucket aggregation
  analyze_b.py          # lens (b) cross-batch union analysis
  analyze_c.py          # lens (c) days-to-fingerprint
  sensitivity.py        # α, D, init, commit-trigger sensitivity
  plots.py              # matplotlib + pgfplots emission
  cli.py                # `python -m sim.cli run|analyze|plot ...`
  tests/
    test_closed_form.py
    test_hand_checked.py
    test_underflow.py
```

Dependencies: numpy, polars (faster CSV than pandas), scipy, matplotlib.
Per-trial RNG seeds derived deterministically from the CLI `--seed` via
blake2b (decision #51). Parallelism via `multiprocessing.Pool` over
(cell × victim_shard) work units (decision #50), sequential trials within
a shard.

## 15. Open / configurable defaults

These are not blocking; defaults locked in spec, configurable via CLI:

- **`B_min`** = `B` (i.e., `B_min` not separately swept; the paper's $B_{\min}$
  is the operating threshold the simulator measures, so we sweep `B` and
  report results as `B_min` recommendations).
- **`δ` (replay tolerance)** — not modeled (no replay attack in scope here).
- **Burn-in length for warm cache:** `N + 100` background queries (covers
  initial transient).
- **`dt` per simulator tick:** 10ms.
- **JSONL gzip compression level:** 6.
- **Parallelism default:** `cpu_count()` (no cap); configurable via `--workers` (per decision #50).
- **Per-trial time budget:** 30s wall-clock; trials exceeding this raise
  and are logged as failures (not silently skipped).

## 16. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Synthetic generator skews early results | Mark all pre-real-data results as `synthetic-only`; do not include in paper figures |
| 100M trial-batch full grid blows compute budget | Adaptive scale-up gates expansion on observed gradient |
| Lens (c) is bootstrap-resampled, not real multi-day | Disclose explicitly in §6.x prose: "multi-day pattern is simulated by replaying one day's trace with jittered intra-day timing, fresh background, and fresh cover RNG"; cite as a methodology limitation |
| `α=0.5` produces saturated candidate sets when `S'` is large | Sensitivity sweep over α reveals; ranking metric is robust to this |
| Strong-attacker assumption "knows all background real" is unrealistic | Reported alongside weak attacker; the strong adversary upper-bounds leakage, which is the right direction |
| Reference-set bias toward crawled pages | Top-10k crawl committed; long-tail bucket dropped (decision #14) |
